## 二、AI 做排版的固定流程（铁律）

```
1. 接收用户需求（自然语言即可，如"帮我做一页：左边是旧方法，右边是新方法"）
2. 分析内容特征 → 按下方「自动匹配表」选模板（用户指定了模板就听用户的）
3. 读对应模板文件（骨架 + class 约定 + 范例页）
4. 需要时打开范例页看真实效果（projects/{id}/slides/N.html）
5. 按模板骨架产出内容页（纯内容 DOM，不写内联样式）
6. 用户验收 → 用户提出调整 → 修改
7. 定稿后 → 执行「沉淀检查」（见第四节），更新模板库
```

**禁止**：不查模板库直接排版、自由创造 class 名、写内联 `<style>`、写死 px。

### 自动匹配后的确认原则

- 匹配结果有 80% 以上把握 → 直接用，产出时告知用户"本页使用了 XX 模板"

## 二·六、项目形态识别（横屏 / 竖屏）★

> **AI 处理任何 PPT 项目时，第一步必须确定它的形态（横屏 or 竖屏），再选模板/看结构。**

**唯一权威来源：项目的 `manifest.json`。**

```json
// 竖屏海报
{ "type": "poster", "ratio": "9:16", "theme": "portrait" }
// 横屏演示
{ "type": "presentation", "ratio": "16:9", "theme": "landscape" }
```

**识别规则：**

| 字段 | 竖屏 | 横屏 |
|------|------|------|
| `type` | `poster` | `presentation` |
| `ratio` | `9:16` | `16:9` |
| `theme` | `portrait` | `landscape` |
| 模板库 | `runtime/layouts/portrait/` | `runtime/layouts/presentation/` |
| 页面结构 | `slides/N.html` | 新架构 `slides/N.html` / 老项目根目录 `N.html` |

**硬规则：**
1. **每个项目必须建 `manifest.json`**，`type`/`ratio`/`theme` 必填——没有 manifest 的项目，AI 必须先补建才能处理
2. AI 判断形态：读 manifest → 竖屏走 portrait 模板库，横屏走 presentation 模板库
3. 形态错了会连锁错（模板、viewer、页面结构全错），所以**先读 manifest 再动手**是第一步铁律
4. 页面引用格式见 `PREFERENCES.md` 的编号规范

**已建档项目：**
- `projects/course-ip-20260809` → 竖屏海报（poster / 9:16 / portrait）
- `product-roadshow-20260728` → 横屏演示（presentation / 16:9 / landscape，含 pages 标题元数据）

## 三、内容页输出硬性规则（横屏竖屏通用）1. 页面结构只保留 `.slide` 内容 DOM，**不写 `<head>`、不写内联 `<style>`、不写 `<script>`**
2. 样式全部来自主题 css（`runtime/themes/landscape.css` / `portrait.css`），只使用模板规定的语义 class
3. 字号/间距**禁止写死 px**，由主题容器单位控制
4. 品牌栏复用（模板中有现成片段）：
   ```html
   <a href="index.html" class="brand"><img src="logo.png" alt="MIIFIRE"><span>觅火 MIIFIRE</span></a>
   ```
5. 内容页不加 PC 居中盒子（max-width + margin auto），宽度由查看器统一控制
6. 关键词强调用 `.gold` / `.kw` 类（金色强调），禁止自造高亮方式

## 四、沉淀机制（排版知识飞轮）★

**每次页面定稿后，必须执行沉淀检查**（与「改完代码等确认」同级的工作流铁律，不许跳过）：

| 情况 | 动作 |
|------|------|
| ① 用的布局模板库里已有，无调整 | 在模板文件「范例页」列表补一行引用 |
| ② 布局大体相同，但用户调整了细节（间距/对齐/变体/结构） | 在对应模板「变体」节记录调整内容 |
| ③ 布局是全新的 | 新建模板文件（照固定格式），并更新本手册模板清单表 |
| ④ 同类模式出现 2-3 次 | 合并归纳，升级模板主骨架 |

**模板文件固定格式**（新建模板必须遵守）：

```markdown
# 模板名
> 一句话用途

## 适用场景
（什么时候选这个模板）

## DOM 骨架
（代码块：完整骨架，含语义 class）

## class 约定
（每个 class 的作用）

## 变体
（已有变体记录：来源页、改动点）

## 范例页
- projects/{id}/slides/N.html — 一句话说明这页怎么用这个模板

## 注意事项
（该模板特有的坑/细节）
```

## 五、与引擎的关系

- 本模板库是**排版层**资产，与引擎功能层（侧边菜单/备注等）完全解耦
- 模板只描述"内容页长什么样"，不描述交互
- **引擎已实现（2026-08-16）**：`runtime/shell.js` + `runtime/features/`（9 模块），
  模板骨架即 `slides/N.html` 的标准产出格式；QA 校验见 `scripts/validate-project.js`
- 模板库更新不影响线上任何项目（纯文档），按 `/ppt-push` 规则推送

## 六、用户评价系统（审美偏好档案）★

> **核心思想：用户对页面的主观评价是最高价值的沉淀资产。**
> "这页为什么好"比"这页用了什么结构"更能指导未来的排版。
> 每次用户评价 → 记录原文 → 提炼偏好信号 → 写入偏好档案 → AI 以后排版必读。

### 6.1 评价怎么产生（用户视角）

用户在看页面时随口说（口头、文字都行）：
- "这一页我很喜欢，留白大，看着舒服"
- "这个编号+金色关键词的节奏特别好"
- "数据页就应该是大数字压阵，别搞太多字"

AI 记录这些**原始评价**（含页面引用），不打断、不追问太多。

### 6.2 评价怎么沉淀（AI 动作）

每收集到一条评价，AI 执行：
1. 记录原始评价 → 追加到 `PREFERENCES.md`（含页面引用）
2. **提炼偏好信号**：从评价里抽出可复用的审美原则（如"用户偏好大留白"、"编号要点节奏"、"大数字主导"）
3. 关联到对应模板（这条评价是在哪个模板的页面上产生的）
4. 更新 `PREFERENCES.md` 的偏好清单

### 6.3 AI 排版时怎么用评价

```
1. 读 README（模板清单）
2. 读 PREFERENCES.md（偏好档案）← 新增必读步骤
3. 选模板时：参考该模板的历史评价（"用户多次夸 X" → 优先该模板 / 强化 X 特征）
4. 排版时：应用提炼的审美原则（留白、层级、金色用法、数字主导……）
5. 原则冲突时：用户直接指令 > 偏好档案 > 模板默认
```

### 6.4 偏好档案格式（PREFERENCES.md）

```markdown
## 模板名 / 页面引用
- 用户评价原文：……
- 提炼偏好信号：……
- 关联模板：……
```

### 6.5 评价与沉淀机制的关系

| 资产 | 回答的问题 | 存放 |
|------|-----------|------|
| 模板 | 页面"长什么样"（结构） | runtime/layouts/{presentation,portrait}/*.md |
| 规范 | 页面"必须遵守什么"（规则） | POSTER_PROJECT_CHECKLIST.md / README 输出约束 |
| 偏好档案 | 页面"怎样才合用户审美"（为什么好） | runtime/layouts/PREFERENCES.md |

三者共同构成 AI 排版的完整参考：**结构 + 规则 + 审美**。
