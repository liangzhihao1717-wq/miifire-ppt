# 审美偏好档案（PREFERENCES）

> **AI 排版必读文件**：这里沉淀用户对页面的主观评价与提炼出的审美偏好。
> 每次做新页面，选模板和排版时都必须参考本档案。
> 新增评价的流程：用户评价 → 记录原文（含页面引用）→ 提炼偏好信号 → 追加到本文件。

---

## 使用规则

1. 本文件是**用户的审美意志**，优先级仅次于用户直接指令
2. 每条记录包含：页面引用 + 用户评价原文 + 提炼的偏好信号 + 关联模板
3. 偏好信号是可执行的原则（"排版时应该……"），不是感受描述
4. 同一模板积累多条评价 → 归纳成模板级设计原则

## 页面引用格式（编号规范）

**原则：身份（ID）与顺序（编号）分离。**

```
项目编号：{项目名}-{YYYYMMDD}    如 course-ip-20260809（全局唯一）
页面 ID：语义 slug（身份，永不变）  如 prelude、ch1-positioning（全局唯一）
页面编号：n（顺序，可变）          如 1、2、3……（增删插入后重排）

完整引用（评价/引用必用 ID）：
  projects/{项目编号}/页#{页面ID}    如 projects/course-ip-20260809/页#ch2-content
```

- **引用一律用页面 ID，禁止只用编号**（"第 3 页"会因重排而指错页）
- 增删/插入页面时：编号 n 与文件序号重排，**ID 保持不变**，所有引用、评价、模板范例不受影响
- 页面 ID 规则：语义化英文短横线命名（如 `trust-first`），唯一、可读、不依赖位置
- 页面删除时：ID 从 manifest 移除，评价记录保留并标注"页面已删除"
- 页面内容大改后，旧评价如不适用需复核（评价跟着页面走）
- 页数由 manifest 的 `total` 校验

### benefits 锚点式编号列表 — projects/agent-meet-20260818/页#benefits

- **用户评价原文**：
  - "第 4 页的这个样式我非常喜欢，这种排版我非常喜欢。"
  - "这 4 段的前面都有一条竖线，这个竖线加得非常漂亮；竖线前面又是大编号，编号很大，又跟这一段是居中对齐的。"
  - "所有小字、高亮字的前后都加空格，用户看起来非常醒目、明确、清楚。"
  - "这个页面你很难基于这个页面的需求，再做得比这个排版更好了。"
- **提炼偏好信号**：
  1. **多段信息页用"锚点式编号列表"**：当一页承载多段（每段 = 大标题 + 描述）信息时，用「大号金色编号 + 金色渐隐竖线 + 内容块」竖排列表；编号是视觉锚点，不是角落小标签。
  2. **编号大号、金色、垂直居中于整段**：编号与"标题 + 描述"的组合（整段）垂直居中对齐（align-items: center），不是顶部对齐。
  3. **金色竖线上下渐隐**：竖线用渐变（顶部底部淡、中间亮），不是生硬实线。
  4. **高亮关键词前后留白**：金色关键词（.kw）前后加间距（margin: 0 0.5cqw），不与相邻文字堆叠，醒目明确。
  5. **层级分明**：主标题大字暖白（金色用金属渐变）、描述小字弱化（金色用纯色金）。
- **关联模板**：benefits（runtime/layouts/portrait/benefits.md）
